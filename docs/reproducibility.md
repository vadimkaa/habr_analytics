# Воспроизведение результатов

Пакет содержит исходный срез метаданных, производные числовые таблицы и код,
на основании которых собрана статья. Все команды выполняются из корня проекта.

```bash
python -m pip install -r requirements.txt
python -m pytest
python run_analysis.py --metrics-only
```

`--metrics-only` использует приложенные лексические признаки и не требует
полных HTML-текстов сторонних публикаций. Для повторного вычисления этих
признаков необходимо заново скачать тексты по манифесту: содержание живых
страниц может отличаться от среза 2026 года.

## Происхождение архивного среза

В `data/` хранятся два зафиксированных файла `habr_ai_ml_raw.jsonl.gz` и
`habr_wide_raw.jsonl.gz`; их SHA-256 и исходные определения записаны в
`data/input_manifest.json`. Архив был собран 9–10 ноября 2026 года, но
первоначальный полный лог сетевых запросов и точная последовательность страниц
не сохранились. Публичный `01_fetch_metadata.py` предназначен для повторного
сетевого сбора и не гарантирует получения идентичного архивного среза.
Замороженные исходные файлы позволяют воспроизвести *расчёты*, а не заново
воссоздать историческую выдачу сайта.

## Какие этапы воспроизводятся


| Уровень | Что можно сделать из этого репозитория |
|---|---|
| Числовой анализ | `run_analysis.py --metrics-only` заново считает все таблицы, рисунки и текст статьи из приложенных метаданных и лексических метрик; `article.md` сравнивается побайтово, JSON-результаты — с численными допусками; сохранённые модели CatBoost не переобучаются |
| Извлечение текстовых признаков | Офлайн не повторить: полных текстов чужих статей здесь нет. `fetch_texts.py` скачивает их заново по `data/text_sample_manifest.json`, но живые тексты могли измениться |
| Повторный сбор с Хабра | Скрипты сбора дают новый срез, а не архив 9–10 ноября 2026 года. После реформы форматов от 9 ноября 2026 года состав публикаций, отбираемых прежним фильтром, может отличаться от исторического корпуса |

Анализ не обращается к сети, но установка зависимостей требует доступа к индексу пакетов. Продолжительность пересчёта зависит от оборудования; существенная часть стоимости приходится на бутстреп и регрессии. При пересчёте в разных вычислительных средах результаты с плавающей точкой могут немного различаться из-за особенностей численных библиотек. Поэтому GitHub Actions побайтово сверяет с репозиторием `article.md`, а расчётные JSON — по структуре и значениям: строки, целые числа и набор полей сравниваются строго, обычные вещественные числа — с абсолютным допуском 1e-7 и относительным 1e-8, а границы авторских бутстреп-интервалов `ci95_author` — с абсолютным допуском 0.001. PNG могут отличаться из-за версий графических библиотек, доступных шрифтов и особенностей окружения; побайтово они в CI не сравниваются.


Этап 17 повторяет расчёт и сверяет с `data/results/17_final_sensitivity.json`, не перезаписывая его. Структура, хеши, размер выборок, булевы признаки и содержательные строки сравниваются точно. Версии среды и число итераций квантильного решателя — диагностика, а не оцениваемые метрики. Для дополнительных результатов относительный допуск 1e-5, базовый абсолютный — 1e-6; для квантильных оценок — 5e-4, компонент модели со случайным эффектом — 2e-4, границ интервалов по эпизодам и контрольным неделям — 0.15 п.п., по возрастным окнам — 0.02 в отношении медиан, для внутриавторских корреляций и разностей удельных метрик — 0.01. Размер группы в расчёте мощности может отличаться на одну статью из-за округления вверх. Сходимость численной задачи обязательна; при достижении предела итераций медианной регрессии используется решение задачи линейного программирования. Сохранённые значения, прошедшие сравнение, служат источником публикационных таблиц и дополнительных рисунков. При необходимости получить отдельный результат без изменения снимка: `python 17_final_sensitivity.py --check --output /tmp/sensitivity.json`.


Этап 19 проверяет медианы VPD в интервалах 9–15 и 16–22 (включительно, МСК), а также корреляции с плотностью по объединению двух корпусов. В объединении каждая статья учитывается один раз; результаты рассчитываются на прежних зрелых годовых выборках каждого корпуса, без использования данных об отсутствующих хабах. Точные округлённые значения контролируются отдельным тестом и общим сравнением JSON.

## Источник правды текста

Каноническая цепочка: `article_template.md` + JSON-результаты → `10_build_article.py` → `article.md` → `13_build_docx.py` → `article.docx`. Правки текста вносятся в шаблон (или прямо в `article.md` с переносом в шаблон), затем пересобираются оба файла; ручные правки docx при следующей сборке теряются. Основные расчётные таблицы и многие числа подставляются из JSON; отдельные округлённые значения и поясняющие примеры приведены в авторском тексте.

## Повторяемость на новом Хабре

Общая лента статей, новостей и постов существовала до 9 ноября 2026 года
(см. источники [12] и [17] в `article.md`). Реформа 9 ноября изменила
типизацию материалов и возможности фильтрации по форматам. Поэтому:

- **Воспроизведение архивных результатов** опирается на закреплённые
  метаданные, результаты и вычислительный код; оно не зависит от нового
  интерфейса ленты.
- **Повторный сбор** через старый `postType` может получить другой состав
  публикаций. Требуются проверка фактического ответа API, сохранение формата
  и версионные правила отбора, отдельно для исторических и новых материалов.
- **Новая плотность ленты** должна учитывать весь доступный поток, а также
  отличать поток выбранных хабов от персональной выдачи читателя. Последнюю
  без данных о показах восстановить нельзя.
- **Проверка после реформы** требует повторных замеров счётчиков к одинаковому
  возрасту статьи (например, 1, 3, 7, 30 суток). `collect_panel.py` служит
  заготовкой, но пока не догружает по ID статьи, выпавшие из свежего обхода.

Сравнение до/после реформы само по себе не является причинным экспериментом:
за это время могли измениться аудитория, темы, авторы и интерфейс Хабра.
Подробнее — раздел 13 статьи.

## Определения и ограничения

- VPD — накопленные просмотры / возраст. Это не текущий трафик и не корректировка, устраняющая возрастной эффект. Для сравнений, растянутых на годы, основной метрикой служит перцентиль просмотров внутри месяца публикации (`month_pct`): он снижает влияние возраста статьи и роста платформы, но не снимает его полностью.
- Время — Europe/Moscow. Выходные — суббота/воскресенье за вычетом рабочих дней производственного календаря: рабочие субботы (например, 01.11.2025) отнесены к будням. Праздничные будни входят в будни основного сравнения; их анализ — отдельная задача.
- Праздники — нерабочие будни по производственному календарю РФ 2016–2026 (`data/production_calendar_2016_2026.csv`, источник xmlcalendar.ru по постановлениям Правительства РФ о переносах; дата загрузки 11.11.2026, перекрёстная проверка 2024–2025 — КонсультантПлюс/Контур). Переносы учитываются, рабочие субботы остаются рабочими днями, одноразовые нерабочие дни указов 2020–2021 годов в праздники не включаются и проверяются отдельно. Ключевые даты закрыты тестом.
- Исходная контрольная модель LightGBM предсказывала накопленные просмотры с пуассоновской функцией потерь. Финальные модели CatBoost обучались на log1p-просмотрах; основная метрика задачи A — средняя корреляция Спирмена внутри календарных месяцев. MAE на log1p-шкале приведена отдельно.
- Погода не анализируется: входной CSV отсутствует.
- Срез относится преимущественно к публикациям до реформы форматов 9 ноября 2026 года. Общая лента разных типов материалов существовала уже с 2023 года; реформа изменила классификацию публикаций и фильтрацию по форматам. Прежний фильтр «статья» не гарантирует ту же совокупность публикаций при повторном сборе.
- У инфобеза покрытие начинается 23.06.2025. Для широкого календарного анализа используется 24.06.2025 и позднее; плотности требуется ещё день истории. Полнота внутри интервала не доказана журналом сбора.
- Корпуса пересекаются. Текстовая смесь 1200:400 задана экспертно и не репрезентативна для всего Хабра.
- `data/preprocessing_baseline_*.jsonl` — числовые метрики тех же текстов при упрощённой предобработке (без односимвольных слов, предложения по регулярному выражению); по ним строится таблица «Насколько всё зависит от предобработки». `data/image_counts.csv` — число иллюстраций в каждой статье текстовой выборки (без формул-картинок); текстов в обоих файлах нет.
- Авторская история модели содержит только число ранее опубликованных статей. Будущие счётчики исключены. Но все обучающие цели измерены поздним срезом: временной holdout остаётся ретроспективным.
- Сетка слотов и различия медиан не измеряют эффект переноса одной и той же статьи.
- Бутстреп по авторам не учитывает все зависимости между авторами; для эффекта выходных дополнительно приведён бутстреп по неделям публикации. BH относится только к указанному семейству проверок. Исследование разведочное.

## Заморозка данных

Снапшот счётчиков (9–10 ноября 2026 года) зафиксирован как финальный для этой версии статьи и кода. Все входные файлы защищены SHA-256 в `data/input_manifest.json`; `run_analysis.py` отказывается считать на изменённой выгрузке. Пересбор данных потребует повторной сверки чисел статьи — все значения подставляются из `data/results/` через `10_build_article.py`.

## Эксперимент прогнозирования

В `experiments/catboost/README.md` приведены команды обучения, описание
проверок A/B1/B2, временных разбиений и сохранённых результатов. По умолчанию
`run_analysis.py` не переобучает модели, а использует зафиксированные метрики.

## pandas: окружение релиза и диагностика исторической ошибки

Описанная в статье ошибка с микросекундами вместо ожидаемых наносекунд обнаружилась при использовании **pandas 3** в рабочей сессии. Для воспроизведения текущих результатов репозиторий фиксирует **pandas 2.2.3** в `requirements.txt`. Эти версии относятся к разным этапам работы и не должны смешиваться при интерпретации исторической ошибки.
