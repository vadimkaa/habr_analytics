# Устройство проекта

Исследование разделено на два независимых вычислительных контура. Основной
анализ (`01_*.py` — `15_*.py`) рассчитывает описательные показатели, таблицы
и графики статьи. Общие определения и правила подготовки данных — в
`habrpub/analysis.py` и `habrpub/calendar_analysis.py`. Контрольная модель
LightGBM вынесена в `habrpub/legacy_model.py`; `08_model.py` запускает её
оценку и диагностические рисунки.

Эксперимент CatBoost запускается через
`experiments/catboost/run_experiments.py`. Эта команда лишь диспетчеризирует
этапы из `experiments/catboost/stages/`:

| Модуль | Назначение |
|---|---|
| `common.py` | Разбиения, вычисление метрик, реестр и сохранение предсказаний |
| `fit.py` | Контрольные модели, функции потерь, подбор на validation и выбор финалистов |
| `policy.py` | Рейтинги A/B1/B2, сравнение с правилом выходных |
| `robustness.py` | Проверки на других периодах, подвыборках и корпусах |
| `reporting.py` | Калибровка, итоговые таблицы, фиксация результатов |

`src/` содержит статистические и модельные примитивы, конфигурации
хранятся в `configs/`, а зафиксированные данные проверок — в `results/`.
Разделение стадий не меняет методику исследования: конфигурации моделей,
значения seed, сохранённые модели и предсказания остаются прежними.

## Какие результаты пересчитываются

- `python run_analysis.py --metrics-only` обновляет описательные
  расчёты, графики и `article.md` по готовым лексическим признакам;
  модели CatBoost при этом не переобучаются.
- `python experiments/catboost/run_experiments.py audit` проверяет входы.
- `python experiments/catboost/run_experiments.py all` запускает полное
  обучение и проверки; это значительно более тяжёлая операция.
- `python -m pytest` выполняет тесты обоих контуров.

Имена отдельных контрольных конфигураций внутри JSON сохранены, чтобы
не нарушать ссылки между описанием эксперимента, модельными артефактами и тестами.
