# Прогноз популярности и выбор времени публикации

Этот эксперимент сравнивает CatBoost и контрольные модели LightGBM на
фиксированном срезе статей. Он разделяет три разных вопроса:

- **A — полный прогноз:** как модель ранжирует по просмотрам разные статьи;
- **B1 — фиксированный профиль:** есть ли календарный сигнал при неизменных
  характеристиках автора и статьи;
- **B2 — персональный рейтинг:** какое место фактический слот статьи занимает
  среди допустимых альтернатив для этой же статьи.

Слоты B1/B2 описывают ассоциации в исторических данных. Просмотры одной
статьи при переносе в другое время неизвестны; причинный эффект не измерен.

## Как запустить

Из корня репозитория (Python 3.12):

```bash
python -m pip install -r requirements.txt
python -m pip install -r experiments/catboost/requirements-catboost.txt
python -m pytest
python experiments/catboost/run_experiments.py audit
python experiments/catboost/run_experiments.py all
```

Последняя команда последовательно запускает сбор контрольных показателей,
сравнение функций потерь, выбор модели на validation, оценку A/B1/B2,
проверки устойчивости, калибровку и построение отчёта. Это ресурсоёмкая
процедура; для чтения статьи переобучение не требуется.

Можно выполнить одну стадию:

| Команда | Назначение |
|---|---|
| `freeze` | Зафиксировать входы и контрольные показатели |
| `audit` | Проверить данные и контрольные суммы |
| `control`, `loss`, `loss_w2`, `tune` | Контроли, функции потерь, ограниченные варианты обучения |
| `select` | Зафиксировать кандидатов и победителей по validation |
| `policy` | Сравнить A/B1/B2 и записать поартикульные результаты |
| `robust`, `final` | Временная и авторская устойчивость |
| `calibration` | Проверить прогноз абсолютного уровня |
| `report` | Построить графики и `results.md` |

## Данные и принципы оценки

Корпуса и временные границы записаны в `configs/splits.yaml`; функции потерь
и наборы признаков — в `configs/losses.yaml` и `src/features.py`;
критерии отбора и допустимые слоты — в `configs/protocol_v1.yaml`.

Победители выбираются только по validation и сохраняются в
`results/selected_policies.json`. Период `audit_exposed` используется лишь
для ретроспективной оценки. Спирмен внутри месяцев — основная метрика
ранжирования популярности; абсолютные прогнозы дополнительно проверяются
по MAE и калибровке на `log1p`-шкале.

Для выбора времени используется разность корреляций Δρ между score модели
и признаком выходных на одних наблюдениях. Интервалы считаются парным
кластерным бутстрепом по авторам, дополнительно — по неделям. Для B2
проверяются абсолютная, относительная и ранговая оценки фактического слота;
в основной статье приводится ранговая. Достаточность поддержки слота
проверяется по train, а фактическая будущая плотность ленты не используется.

## Где результаты

- `results/metrics/`: метрики, калибровка, устойчивость;
- `results/selected_policies.json`, `policy.json`: зафиксированный выбор;
- `results/predictions/article_level/`: score каждой статьи;
- `results/models/`: сохранённые модели;
- `results/figures/`: диагностические рисунки;
- `results/results.md`: сводные таблицы;
- `results/registry.csv`: журнал запусков (каждая запись с отдельным `run_id`).

Большие таблицы альтернативных слотов B2 для **двух выбранных моделей**
(ИИ/МЛ и пяти хабов) не входят в основной репозиторий. Они размещаются в
отдельном ZIP-архиве GitHub Release. Полный набор таблиц также можно
пересчитать стадией `policy`. Идентификаторы конфигураций зафиксированы в описании эксперимента: менять их без
переучёта связанных JSON и моделей нельзя.
